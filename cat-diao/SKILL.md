# 猫叼

这是一个自包含的本地技能，目录名是 `cat-diao`。电脑端程序在本技能的 `scripts/`。2.0 安装包不放在仓库里，需要主人在本机签名后生成。根据本 `SKILL.md` 的实际绝对路径定位脚本；不要假设当前工作目录、磁盘盘符或某一台电脑的私人路径。仅在 Windows 本机执行。

猫叼用于看画面、点画面的真机验证。它不替代 ADB：没有 logcat，没有断点，也不能静默安装。首次把安装包送到手机时，需要用户在手机上点一次确认。

## 安全

2.0 配对使用一次性的 6 位核对数字。数字只出现在手机对话框和电脑终端上，两边一致后用户才点「允许」。配对令牌不会出现在网络请求里。之后每一次请求都带签名。内容在局域网上仍是明文，只在用户信任的 Wi-Fi 上使用。不要把令牌、API key、`.env`、`connection.json`、`collector.env` 或密钥写进技能目录或 Git。

## 首次使用

猫叼小窝（个人数据）的位置由用户选择，记在 `%USERPROFILE%\.catdiao\config.json`，不放在 AppData 里，避免被商店版沙箱挡住。也可以用环境变量 `CATDIAO_NEST_HOME`。都没设置时：技能在本仓库内就用仓库根目录的 `data/`（git 忽略）；否则用 `%LOCALAPPDATA%\猫叼小窝`。

运行 `scripts/setup.ps1`。要换位置时加 `-NestDir <文件夹>`。setup 只把旧位置里缺少的文件复制过来，不会删除或覆盖已有收藏、配对或配置。若目标小窝里已经有用户数据，不会自动并入另一份旧数据。

setup 创建 Python 环境、安装 Excel 依赖、设置登录后后台接收，并尝试为小窝接收端口添加「专用网络、仅局域网」的入站防火墙规则。规则按端口，不按 `python.exe`。没有管理员权限时，setup 会打印需要手动运行的命令，不会因此失败。若当前网络是公用网络，会提示改成专用网络。

让用户安装 2.0 后再配对。旧的 1.14 安装包不能当作 2.0。2.0 是另一个应用包名，可以和旧猫叼同时出现在手机上，但两边不能一起运行，否则端口冲突。手机上还没送出的收藏、配对和系统权限不会迁移。电脑上的台账还在。新的发布签名不能覆盖旧的调试签名；发布前必须得到主人同意做一次卸载或强制停止后再安装。钥匙由主人在仓库外创建并做两份备份，见 `docs/signing-2.0.md`。

第一次连接看 `docs/first-connection.md`。让用户在手机上打开猫叼，点「开始连接」。电脑运行 `scripts/run.ps1 pair`。没有别的参数时，这条命令会自己找手机，大约等 60 秒。它先查 mDNS 服务 `_catdiao._tcp`，再发原来的局域网广播。找到后，终端和手机各出现同一个 6 位数字，一致再点「允许」，不同就点「拒绝」。

也可以把手机上的这句话原样发给电脑上的 AI 工具：`请运行 cat-diao 的 scripts\run.ps1 pair，它会自己找到这台手机。`

还是找不到时，让用户点手机上的「还是连不上」。常见原因：两台设备不在同一个 Wi-Fi；公司或访客 Wi-Fi 不让设备互访，可以让手机开热点、电脑连上这个热点；电脑网络是「公用」时，防火墙规则不会放行，要改成「专用」。自动发现失败时，在手机「开始连接」页复制地址或扫二维码，再运行 `scripts/run.ps1 pair --address <地址>`。不要因为一次连接失败就重新配对。蓝牙备用要等这次配对完成，未配对时手机不会把人带进一个点了没反应的按钮。

所有运行命令均以 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File <本技能绝对路径>/scripts/run.ps1` 开头。`phone` 后接手机命令，`collector` 后接收藏命令。

## 权限

收藏不需要额外权限。发文件和剪贴板只需要网络。看画面、点画面需要屏幕控制。调节亮度需要「修改系统设置」。悬浮窗可选。安卓 13 及以上从浏览器或文件管理器安装时，先在应用信息页点右上角 ⋯ →「允许受限设置」。省电白名单和自启动说明见 `docs/permissions-2.0.md`。通知里可以「暂停遥控」。首页可以直接撤销这台电脑的连接。

## MCP

在本技能 `scripts/` 下运行 `python mcp_server.py`，供支持 MCP 的客户端做看画面、点画面的真机验证。它不替代 ADB。工具包括截图、点按、滑动、主页/返回/最近任务/通知、打开应用、发送文件、壁纸和状态。说明见 `docs/mcp-2.0.md`。本轮不自动解析已保存的文章。

## 蓝牙备用连接

保留原有应用配对，不因为 IP 变化重新配对。蓝牙备用要等第一次 Wi-Fi 配对完成。还没配对时，手机上的蓝牙入口会回到连接步骤，并写明「先连上电脑，再设置蓝牙备用。」配对之后，在「已连上」里点「设置蓝牙备用连接」，由用户允许附近设备，并在系统蓝牙设置中将手机与电脑配对一次。这一步不能由 AI 代替用户点击确认。双向校验使用已保存的配对令牌，令牌本身不放进蓝牙载荷明文。电脑首次发现目标后把蓝牙地址保存在个人配对文件中，不放进技能包。

`/health` 的 `bluetooth_connection` 与 `phone_connection` 分别报告两条通路。蓝牙连接不等于 Wi-Fi 控制已经恢复；只有 Wi-Fi 恢复后才做屏幕、文件、壁纸和剪贴板操作。不要声称蓝牙已经在这台真机上验证，除非主人安装 2.0 并完成系统配对后测试成功。

## 操作手机

按请求使用 `phone status`、`diagnose`、`apps`、`open <包名>`、`volume <级别>`、`brightness <1-255>`、`send <文件>`、`clipboard-send --text <文字>`、`wallpaper <图片>`、`screen <保存路径>`、`home`、`back`、`recents`、`notifications`、`tap x y` 或 `swipe x1 y1 x2 y2`。`phone get <保存路径>` 只下载用户在猫叼里选定的文件。

点按前先取新截图。受系统保护的页面可能无法截图。锁屏不能代替用户解锁。读取或发送电脑剪贴板前须有用户对该内容的明确请求，不在输出中回显敏感文字。

## 用另一份代码跑现有小窝

新检出的 2.0 仓库自带 `.git` 时，如果不另外指定，小窝会落在这份检出自己的 `data/`。要接着用原来的配对和台账，启动前指到现有目录。接收程序不会删除那个目录里的文件。

在新检出里任选一种：

```
$env:CATDIAO_NEST_HOME = '<现有小窝的完整路径>'
powershell -NoProfile -ExecutionPolicy Bypass -File <新检出>\cat-diao\scripts\start_receiver.ps1 -Restart
```

或只做一次，把目录记进 `%USERPROFILE%\.catdiao\config.json`：

```
powershell -NoProfile -ExecutionPolicy Bypass -File <新检出>\cat-diao\scripts\setup.ps1 -NestDir '<现有小窝的完整路径>'
```

`start_receiver.ps1 -NestDir` 同样可以。Python 入口也认 `--nest`。启动后看本机回环上的 `/health` 和 `run.ps1 collector status` 里的 `nest` 是不是这个目录，再让手机重连。

## 接收与收藏

手机分享的链接、发到电脑的文字和选定文件，由小窝里的 `收藏同步.py listen` 接收。`setup.ps1` 设置登录自启。AI 工具关闭后仍由该后台进程接收。若未运行且端口空闲，可运行 `scripts/start_receiver.ps1`。只运行一个接收程序。

未经用户重新明确要求，不启用定时保活任务。接收端退出时可按用户请求运行 `scripts/start_receiver.ps1` 恢复。不要因读不到配对而提权或重新配对。

电脑会在网络恢复后续连，间隔从约 10 秒逐渐增加到最多 60 秒。手机开机后会尝试拉起服务。首页「已连接」需要当前配对的电脑接收端确认。

用户说「连接猫叼」或状态持续离线时，先检查本机 `/health`（只在这台电脑的回环地址上）。响应含 `phone_connection`、`nest` 和 `firewall`。`firewall.hint` 有字时，把这句话告诉用户。常见情况是当前网络是公用网络，而规则只对专用网络放行，需要到 Windows 设置里把这块网络改成「专用」。`collector status` 里的 `firewall` 是同一份结果。接收程序没运行就启动它，再运行 `phone status`。自动发现失败时，让用户打开手机「开始连接」，复制页面上的地址，再运行 `run.ps1 pair --address <地址>`。只有手机明确显示未配对时才重新 `pair`。不要把「已配对」或一次失败当作已经连上或安装失败。

用户问「刚发的东西在哪」时，用 `collector status` 和当前小窝里的 `收藏台账/` 核对。手机显示「已到小窝」只表示电脑确认收到。收到的文件在小窝的 `手机传来的文件/`。WeKnora 是可选的后续同步：服务地址、专用 API key 和知识库编号只放在该用户小窝的 `collector.env`（`WEKNORA_KB_ID`、`WEKNORA_PERSONAL_KB_ID`、`WEKNORA_CAPTURE_TAG_ID`）。不要把这些值写进技能或仓库。不要把本地收件、网页全文解析与 AI 处理混为一谈。本轮不自动解析文章。

链接资料已入库但网页正文反复失败时，可在接收程序空闲时用 `run.ps1 collector giveup --id <收藏ID> --text <原因>` 把网页状态记为已放弃，链接资料本身保留。

更新技能后运行 `scripts/start_receiver.ps1 -Restart`，再核对 `/health` 的版本是 2.0。
