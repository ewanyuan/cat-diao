# 猫叼



这是一个自包含的本地技能。电脑端程序在本技能的 `scripts/`，手机安装包在 `assets/cat-diao-android-1.14.apk`。根据本 `SKILL.md` 的实际绝对路径定位它们；不要假设当前工作目录或用户的磁盘盘符。仅在 Windows 本机执行。首次应用配对、手机控制和文件传输需可互访的局域网；蓝牙备用连接可找回变化的地址，或在 Wi-Fi 不通时补送收藏。不要求无线调试。



## 首次使用



若本技能位于 cat-diao 仓库内，程序、Python 环境和数据都在仓库里：环境是仓库根目录的 `.venv/`，个人数据是仓库根目录的 `data/`（已被 git 忽略，永不提交）。若 `.venv/Scripts/python.exe` 不存在，运行 `scripts/setup.ps1`。不在仓库内时才回退到 `%LOCALAPPDATA%/猫叼小窝/`。setup 创建独立 Python 环境，安装 Excel 依赖，迁移能找到的旧配对与收藏，设置登录后后台接收；不会把凭据写进技能目录。若电脑没有 Python 3，先为当前用户安装 Python，再重试。普通使用不反复执行 setup。已有「猫叼小窝」电脑程序时共用其数据和接收端口，不启动第二个接收程序。



让用户在手机安装本技能 `assets/` 内的 APK 并打开猫叼。接收程序启动后，也可让手机从电脑的 `http://<局域网IP>:8793/cat-diao.apk` 下载。电脑运行 `scripts/run.ps1 phone pair --wait 60`；手机实际出现连接请求时由用户点「允许」，随后按手机内引导完成系统权限。找不到手机先检查同一 Wi-Fi、解锁状态和猫叼是否已打开，必要时从首页右上角「⋯ → 小窝连接」读取连接地址，在 `phone` 后、命令前加 `--address http://IP:8767`。不要因为一次连接失败就重新配对。



所有运行命令均以 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File <本技能绝对路径>/scripts/run.ps1` 开头。`phone` 后接手机命令，`collector` 后接收藏命令。脚本自动使用仓库 `data/`（回退时为 `%LOCALAPPDATA%/猫叼小窝/`）中的配对信息、收藏台账、收到的文件和可选知识库配置。不要把这些个人数据、API key 或运行时环境复制进技能包或提交到 GitHub。



## 操作手机



## 蓝牙备用连接（1.14）



保留原有应用配对，不因为 IP 变化重新配对。手机和电脑需一起升级到 1.14；手机「⋯ → 蓝牙连接」中点「去设置」，由用户允许附近设备，并在系统蓝牙设置中将手机与电脑配对一次。这一步不能由 AI 代替用户点击确认。手机监听猫叼专用 RFCOMM 服务，电脑接收程序自动查找系统已配对的手机；双向挑战必须用原有应用令牌验证成功后才交换地址、传送收藏。电脑首次发现目标后会将蓝牙地址保存在原有个人配对文件中，不放进技能包。



`/health` 的 `bluetooth_connection` 与 `phone_connection` 分别报告两条通路；`needs_bluetooth_pairing` 表示没有找到系统已配对的手机，`unavailable` 表示蓝牙环境不可用。手机状态的 `connection_transport` 为 `wifi`、`bluetooth` 或 `offline`，`bluetooth_state` 指示权限、开关与实际连接。蓝牙连接不等于 Wi-Fi 控制端口已恢复，需分别验证；只有 Wi-Fi 恢复后才运行屏幕、文件、壁纸和剪贴板操作。蓝牙当前支持收藏台账中的链接与文字，文件和直接发送剪贴板仍走 Wi-Fi。不要声称蓝牙端到端已验证，除非真实手机安装新版、授权并完成系统配对后测试成功。



## 操作手机命令



按请求使用 `phone status`、`diagnose`、`apps`、`open <包名>`、`volume <级别>`、`brightness <1-255>`、`send <文件>`、`clipboard-send --text <文字>`、`wallpaper <图片>`、`screen <保存路径>`、`home`、`back`、`recents`、`notifications`、`tap x y` 或 `swipe x1 y1 x2 y2`。`phone get <保存路径>` 只下载用户在猫叼里选定的文件，不代表能任意浏览手机文件。



屏幕点按前先取新截图并查看。屏幕控制与亮度等权限由用户在手机系统页面开启；受系统保护的页面可能无法截图。手机锁屏或长时间熄屏可能暂停连接，不能代替用户解锁。读取或发送电脑剪贴板内容前须有用户对该内容的明确请求，不在输出中回显敏感文字。



## 接收与收藏



手机分享的链接、发到电脑剪贴板的文字、选定发给电脑的文件，由 8793 端口的 `收藏同步.py listen` 接收。技能的 `setup.ps1` 设置登录自启；AI 工具关闭后仍由该后台进程接收。若未运行且端口空闲，可运行 `scripts/start_receiver.ps1`。同一端口只运行一个接收程序，不用旧的 8791 剪贴板监听作为主要入口。



2026-10-08，用户要求取消反复弹出命令窗口的定时保活。`CatDiao Receiver Recovery` 任务已删除，`setup.ps1` 不再自动安装它；未经用户重新明确要求，不启用定时保活。原登录自启保留。接收端退出时可按用户请求运行 `scripts/start_receiver.ps1` 恢复；不要因读不到配对而提权或重新配对。



蓝牙握手的地址列表必须与安卓一致，只包含 RFC1918 地址：10/8、172.16/12、192.168/16。不要直接用 Python `is_private` 代替；它还包含代理常用的 198.18/15，可能造成两端签名不同。2026-10-07 已修复这一真实握手问题，并确认当前 OPPO Android 12 与 Windows 的蓝牙通路连接成功。



电脑端接收程序运行时，会每 10 秒自动探测已配对手机，每次总探测时间最多 10 秒；同一可互访 Wi-Fi 恢复后，手机地址和待送达收藏会自动恢复。手机打开首页或点「重新检查」会向电脑接收端发起真实检查，最多 10 秒显示成功或未连接；后台重试保留已完成结果，不一直显示「正在重连」。首页「已连接」需要当前配对的电脑接收端确认，仅收到电脑控制请求不代表收藏接收程序在运行。1.14 的手机与电脑端需一起更新。



用户说「连接猫叼」「重新连接猫叼」或状态持续离线时，先检查本机 `http://127.0.0.1:8793/health`；1.14 的响应含 `phone_connection` 的真实探测状态、开始和结束时间、`elapsed_ms`。若接收程序未运行且 8793 端口空闲，启动它，再运行 `phone status` 查看手机地址、权限及待送达数量。1.14 的手机状态还包含 `computer_connection_state`、本次检查时间和错误、`computer_retry_in_progress`；不要从旧版本的一句「正在自动重连」推断实际有探测在执行。自动发现失败时，让用户打开猫叼首页右上角「⋯ → 小窝连接」，提供其中的当前连接地址，再用 `phone --address http://IP:8767 status`。只有手机明确显示未配对时才重新发起 `pair`，由用户在手机确认。查看 `capture_pending_count` 和 `capture_sync_error`；待送达收藏应在连接后自动补送，再核对电脑台账。不要把「已配对」或一次连接失败当作当前已连通或安装失败的证据。



用户问「刚发的东西在哪」时，用 `collector status` 和仓库 `data/收藏台账/` 核对。手机显示「已到小窝」只表示电脑确认收到；月度 Excel 和 SQLite 记录才是电脑落盘的依据。收到的文件在 `%LOCALAPPDATA%/猫叼小窝/手机传来的文件/`。WeKnora 是可选的电脑端后续同步：只有服务地址和专用 API key 配在该用户目录的 `collector.env`、且服务可用时才尝试入库；不要把本地收件、网页全文解析与 AI 处理混为一谈。



1.14 会按实际传输大小拆分长文字收藏并连续补送；配对弹窗只批准其中显示的电脑，另一条请求不能替换它。下载中断会报错并清理本次残缺文件，已有文件不会被覆盖。月度台账批量刷新保留用户反馈与备注，知识库同步期间仍可接收新收藏。更新技能后运行 `scripts/start_receiver.ps1 -Restart`，再核对 `/health` 的版本，确保当前运行的是更新后的接收程序。
